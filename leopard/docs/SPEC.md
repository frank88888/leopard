# BAR 台(水果狸 / 小馬莉)遊戲規格書

版本:v1.0  日期:2026-10-17  狀態:已定稿,M1~M5 已實作(見第 16 節實作紀錄)

## 1. 專案概述

在 PC 上以遊戲引擎重現台灣街機「BAR 台」。
玩家投幣換分,在 8 種圖案上押分,按下啟動後跑燈繞圈,停在哪個圖案就依倍率贏分,
贏分後可「比大小」加倍或「收分」。

> 備註:本專案定位為**模擬/娛樂軟體**,只使用虛擬分數,不含任何實際金流、兌換或出幣功能。
> 台灣刑法對賭博電玩有相關規範,硬體化或營運前請自行評估法規。

### 1.1 建議技術

- 引擎:**Godot 4.x(GDScript)** — 開源免費、2D 輕量、輸入/音訊/場景系統足夠。
  Unity 也可行,若偏好 Unity,章節 3~9 的邏輯規格不需改動,僅第 10 節的目錄結構要換。
- 邏輯與表現分離:遊戲規則(押注、機率、結算、比大小)寫成**不依賴 UI 的純邏輯模組**,
  方便做自動化測試與蒙地卡羅模擬(驗證回報率)。

## 2. 名詞

## 5. 跑燈環

### 5.1 格數與座標

- 每邊 9 格、四角共用 → 總計 **32 格**(4×9 − 4)。
- 索引 0~31,**順時針**。索引 0 = 上邊中間(BAR,啟動起點)。
  - 上邊:28,29,30,31,**0**,1,2,3,4
  - 右邊:4~12  下邊:12~20  左邊:20~28(角落 4、12、20、28 共用)
- 若你想要 36 格(四角不共用)請告知,只需改設定表。

### 5.2 格子配置(草案)

32 格內各圖案數量,另加 2 格「LUCK」(送燈/加碼):

| 圖案 | BAR | 77 | 雙星 | 西瓜 | 鈴鐺 | 綠果 | 柳橙 | 荔枝 | LUCK |
|---|---|---|---|---|---|---|---|---|---|
| 格數 | 1 | 2 | 2 | 3 | 4 | 4 | 6 | 8 | 2 |

排列規則(寫入 `ring_layout` 設定表,正式排列待設計):
- 相同圖案不相鄰;兩個 77 大致對稱;BAR 的對面放 LUCK 或 77,讓視覺分散。

> 重點:**格子數量不等於中獎機率**。中獎結果先由機率表決定「圖案」,
> 再從該圖案的格子中隨機挑一格作為停止點(見第 7 節)。

## 6. 操作與押注

### 6.1 投幣

- 面額 1 / 5 / 10 / 50 NTD,投入後 **1:1** 加到 CREDIT。
- PC 版以按鍵模擬:`F1`=1、`F2`=5、`F3`=10、`F4`=50(開發期設定,可改)。
- 若日後接硬體投幣器,以相同事件介面 `coin_inserted(value)` 接入。

### 6.2 押注鍵(8 個,每項目一個)

| 操作 | 行為 |
|---|---|
| 短按(<1 秒放開) | +1 分 |
| 按住 >1 秒 | 持續連加,每次 +1(重複間隔 100 ms,可調) |
| 按住 >3 秒 | 持續連加,每次 +10(重複間隔 100 ms,可調) |

規則:
- 押注額不得超過 CREDIT。+1 連加時 CREDIT 用完即停;+10 連加時剩餘分數不足 10 就**直接停止**(已確認),剩餘分數可再改用短按 +1 或 1 秒以上長按的 +1 押入。
- 連加遇到單項上限(預設 99)也停止,+10 若會超過上限同樣直接停止。
- 每個項目押注上限預設 **99**(可設定)。
- 押注會**立即**從 CREDIT 扣除顯示,啟動後鎖定,結算後清空。
- **續押結合在啟動鍵**(見 6.3),不另設續押鍵。

### 6.3 其他按鍵

| 按鍵 | 條件 | 行為 |
|---|---|---|
| 啟動 / 續押 | 非跑燈中,且(有押注,或有上局押注記憶) | 見下方「續押規則」 |
| 小 / 大 | WIN > 0 且非跑燈中 | 進入比大小 |
| 收分 | WIN > 0 | WIN 以計數動畫轉入 CREDIT,伴隨音效 |

**續押規則**(已確認):
- 系統記住「上局押注記憶」(8 個項目各自的押注額)。每局啟動時以當局實際押注覆寫記憶。
- 局結束後,8 個視窗以淡色顯示上局押注額(提示可續押)。
- 若玩家**沒有改動任何押注**,直接按啟動:以上局相同的押注額自動下注並開始,
  前提是 CREDIT ≥ 上局總押注。
- 若玩家已手動押了任何項目,啟動鍵只以目前押注開局,不套用記憶。
- CREDIT 不足以續押時(已確認):**依比例縮減**押注後開局。
  - 若有 WIN,先自動收分再計算(見下方),以收分後的 CREDIT 為準。
  - 新總押注 = 目前 CREDIT(全部押入),各項目按上局占比分配,採**最大餘數法**取整,使加總剛好等於 CREDIT。
  - 縮減後押注為 0 的項目視為不押;CREDIT 為 0 則不開局。
  - 例:上局 BAR 10、荔枝 30(共 40),CREDIT 20 → BAR 5、荔枝 15。
  - 縮減後的押注同樣覆寫「上局押注記憶」。

- 若 WIN > 0 時直接按啟動(已確認):**自動收分後開始新局**(市面常見做法)。

## 7. 一局流程與機率

### 7.1 狀態機

```
IDLE → (押注、啟動) → SPINNING → RESULT → (中獎) WIN_PENDING → 收分 → IDLE
                                    │                │
                                    │                └→ 比大小 → 贏:WIN×2 /輸:WIN=0 /和:不變
                                    └→ (未中) IDLE
LUCK 格 → BONUS(送燈,見 7.4)
```

### 7.2 結果決定

1. 啟動當下,先用亂數**決定結果**(圖案或 LUCK),再決定停止格索引,**之後才播放動畫**。
   動畫只是呈現,不影響結果。
2. 結果寫入存檔(7.5 斷電保護)後才開始跑燈。
3. 使用 `RandomNumberGenerator`(隨機種子);測試時可注入固定種子。

### 7.3 機率表(實作版)

採「各圖案單位期望回報相同」設計:圖案 i 的出現機率 `p_i = c / 倍率_i`,
不論玩家怎麼分配押注,圖案部分的長期回報率都等於 `c`。

> **修正(實作時發現)**:原草案把剩餘機率全給 LUCK、且送燈平均 1.5 次免費抽,
> 數學上總 RTP 恆 > 100%(1/50+…+1/2 = 0.995,圖案機率已佔滿,送燈只會再加分)。
> 實作改為:LUCK 機率獨立參數,剩餘機率為「LUCK 空燈」(停在 LUCK 格但不送燈)。

參數(`config/odds.json`,後台可調):
- `rtp_target`(預設 0.93)、`luck_bonus_prob`(送燈機率 p_L,預設 0.06)、送燈次數權重。
- 平均送燈次數 E = 1.5。總 RTP = c·(1 + E·p_L),故 `c = rtp_target / (1 + E·p_L)`。
- 送燈中的每一抽**不再連鎖送燈**(抽到 LUCK 視為空燈),所以每抽期望回報恆為 c。
- 剩餘機率 `p_miss = 1 − Σp_i − p_L` 為 LUCK 空燈(須 ≥ 0,後台套用設定時會檢查)。

預設值(rtp_target=0.93, p_L=0.06 → c=0.8532):

| 圖案 | 倍率 | 機率 |
|---|---|---|
| BAR | 50 | 1.71% |
| 77 | 40 | 2.13% |
| 雙星 | 30 | 2.84% |
| 西瓜 | 20 | 4.27% |
| 鈴鐺 | 15 | 5.69% |
| 綠果 | 10 | 8.53% |
| 柳橙 | 5 | 17.06% |
| 荔枝 | 2 | 42.66% |
| LUCK 送燈 | | 6.00% |
| LUCK 空燈 | | 9.11% |

- 玩家沒押的圖案停下來就是沒中,這是主要的「輸」的來源。
- 實測(`tools/simulate_rtp.gd`,各 100 萬局):全押 92.92%、單押 93.13%、隨機押 92.91%,
  都落在目標 93% ± 0.2%。
- 大獎局數、各圖案頻率、LUCK 次數由模擬工具輸出。

### 7.4 LUCK / 送燈(加碼)

觸發 LUCK(送燈)後:
- **送燈**:額外再抽 1~3 次(各自跑燈、各自結算,押注沿用,不再扣分)。
- 次數權重:1 次 60%、2 次 30%、3 次 10%(可調)。
- 送燈期間不連鎖;全部結束後 WIN 一併入帳,進入 WIN_PENDING。

### 7.5 斷電保護

- 在「結果決定後、動畫開始前」與「每次收分/比大小結算後」寫入存檔。
- 重新開機若偵測到未完成的局,直接依存檔結果補完結算,不重抽。

## 8. 跑燈動畫與音效

### 8.1 速度曲線(自由落體)

依自由落體 `s = ½·g·t²`,第 n 步到達時間 `t_n = √(2n/g)`,
第 n 步的間隔 `Δ_n = √(2/g)·(√n − √(n−1))`,隨 n 增加而縮短。

階段:
1. **加速**:由慢到快,使用 `Δ_n`,直到間隔降到最小值 `Δ_min`(預設 40 ms,≈25 格/秒)。
2. **等速**:以 `Δ_min` 繞 K 圈(預設 2~3 圈,每局隨機)。
3. **減速**:將加速曲線**時間反轉**(`Δ` 由小到大),最後一步停在目標格。
4. **停格閃爍**:中獎格閃爍;中獎的押注視窗同步閃爍。

停點對齊:加速步數 A 與減速步數 D 由曲線決定,等速步數 `C` 取
使 `(起點 + A + C + D) mod 32 == 目標索引` 的值(再加上整圈數)。
起點為上一局的停止格(第一局為 BAR / 索引 0)。**(若每局都要從 BAR 起跑請告知。)**

### 8.2 音效

| 事件 | 音效 |
|---|---|
| 每跳一格 | 短「登」聲(`tick`),**每步必播**;高速時需允許重疊/使用多聲道避免被吃掉 |
| 投幣 | 清脆硬幣聲 |
| 押注 | 輕按鍵聲 |
| 一般中獎 | 一般得獎音效 + 分數計數音 |
| 大獎(BAR、77,或單局 WIN ≥ 門檻;門檻 = 單項押注上限 × 5,預設 99×5=495,係數可調) | 特別音效 + 全螢幕閃燈 |
| 送燈 | 專屬提示音 |
| 比大小 贏/輸 | 各一組音效 |
| 收分 | 計數音(逐分跳動) |

音檔來源:**全部以程式合成**(`scripts/audio/sfx_player.gd` 啟動時產生 16-bit WAV),無外部音檔、無版權問題。tick 使用 6 聲道輪播。

## 9. 比大小(Double-Up)

- 條件:WIN > 0。按「小」或「大」。
- 開獎:擲兩顆骰子,取點數和 2~12。
  - **小**:2~6  **大**:8~12  **和(7)**:平手,WIN 不變、可再猜。
- 猜對:WIN × 2;猜錯:WIN 歸零。
- 期望值:P(小)=P(大)=15/36,P(和)=6/36 → 期望回報剛好 1.0(公平)。
- 限制(可設定):連續猜測上限預設 **10 次**(可調);WIN 達上限(預設 9999)時禁止再猜。
- 任何時間可按「收分」結束。
- 呈現:骰子動畫 + 音效。(若偏好撲克牌 A~K 比大小,請告知,規則改為 1~13,7 為和。)

## 10. 後台與帳務

進入方式:隱藏組合鍵(例:長按特定兩鍵 3 秒)+ 密碼。

| 設定 | RTP_base、倍率表、機率表、LUCK 規則、單項押注上限、連按速度、音量、比大小上限 |

## 12. 測試策略

- **單元測試**:押注上限與不足處理、結算公式、比大小規則、存檔還原。實作改用自製輕量執行器 `tests/run_tests.gd`(不需安裝 GUT)。

| 鍵 | 功能 |
|---|---|
| 1~8(含數字鍵盤) | 對應 8 個押注項目(短按 +1,長按連加) |
| F1/F2/F3/F4 | 投幣 1/5/10/50(畫面上方也有 +1/+5/+10/+50 按鈕) |
| 空白 / Enter | 啟動 / 續押 |
| C | 收分 |
| Z / X | 比小 / 比大 |
| 同時按住 Home + End 3 秒 | 進入後台(預設密碼 `1234`,請於後台更改) |

滑鼠 / 觸控也可直接點押注視窗與按鈕。

### 16.2 檔案與資料

- 存檔:`user://save.json`(含 SHA-256 校驗,內容含 CREDIT/WIN/押注記憶/本局結果/帳務)。
- 後台設定覆寫:`user://overrides.json`(同樣含校驗);`config/*.json` 為出廠預設,不被後台改動。
- 稽核紀錄:`user://audit.log`;帳務匯出:`user://accounting_*.csv`。
- `user://` 在 Windows 為 `%APPDATA%/Godot/app_userdata/BAR 台/`。
